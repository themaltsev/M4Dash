# Архитектура v0.1.0 (рабочая)

- `hardware`: периодический sampler в фоне, который публикует типизированный snapshot через `Arc<RwLock<_>>`.
- `llm`: отдельный Tokio runtime и один постоянно работающий `lms log stream --source runtime`, с повторным запуском при завершении. API LM Studio используется только для проверки сервера/инвентаризации.
- `llm::parser`: преобразует runtime строки в события и хранит активные slot-ы в памяти; UI получает снапшоты из общего in-memory store.
- `config`: версионируемый JSON, атомарная запись через временный файл.
- `app`: egui UI, polling только из памяти; сборщики не блокируют интерфейс.

Следующие границы реализации: Win32 taskbar overlay и tray, устойчивое обнаружение устройств/настроек по идентификаторам, дисковые счётчики, LLM inventory и автомат состояний по всем fixture сценариям.
